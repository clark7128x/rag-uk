# rag-uk: проєктні нотатки

## Задача й обмеження

Система шукає відповідь у корпусі українських документів і повертає текст із дослівними цитатами.
Кожна цитата має ідентифікатор чанка-джерела, який розгортається в ідентифікатори абзаців.
Працюють чотири режими пошуку: BM25, векторний, гібрид через reciprocal rank fusion, гібрид із реранкером.
Режим перемикається в `config.yaml` або прапорцем `--mode`.

Обмеження:
- Python 3.11, без фреймворків оркестрації.
- Ключі й назва моделі беруться зі змінних середовища, параметри — з `config.yaml`.
- Набір для оцінки розмічає людина через `tools/label_cli.py`.
- Числа в цьому README з'являються лише після запуску `eval.py`.
- Значення в `config.yaml` — стартові параметри, не підібрані на корпусі.

Корпус у задачі не заданий, тому завантажувач читає `.md` і `.txt` з `data/corpus`.
Файл `data/corpus/example_structure.md` показує формат і підлягає заміні.

## Архітектура

Потік даних: файли → документи → абзаци → речення → чанки → індекси → пошук → контекст → LLM → відповідь із цитатами.

Компоненти:
- `rag_uk/corpus.py` читає файли, нормалізує переноси рядків, рахує відбиток корпусу.
- `rag_uk/chunking.py` виділяє заголовки, абзаци й речення та пакує їх у чанки.
- Чанк зберігає `chunk_id`, `doc_id`, порядковий номер, заголовок розділу, символьні позиції та діапазон абзаців.
- `rag_uk/bm25.py` будує індекс Okapi BM25 у пам'яті.
- `rag_uk/vector.py` кодує чанки обраною моделлю ембедингів і кешує матрицю на диску.
- `rag_uk/fusion.py` зливає два ранжування через RRF.
- `rag_uk/rerank.py` переоцінює кандидатів крос-енкодером.
- `rag_uk/retrieve.py` реалізує перемикання режимів і повертає однаковий список `Hit`.
- `rag_uk/llm.py` викликає OpenAI-сумісний `/chat/completions` і повторює невдалі спроби.
- `rag_uk/generate.py` будує промпт з контекстом і розбирає відповідь.
- `rag_uk/citations.py` витягує ідентифікатори з відповіді й звіряє їх із контекстом.
- `rag_uk/calllog.py` пише JSONL по кожному виклику моделі.
- `eval.py` рахує метрики, `rag_uk/report.py` рендерить markdown.

Кеш індексу лежить у `.cache`: `chunks.jsonl`, `paragraphs.jsonl`, `meta.json`, `embeddings/<профіль>/<відбиток>.npy`.
Зміна тексту документа або параметрів нарізки інвалідує кеш через відбиток.

Ідентифікатор чанка має вигляд `doc_id:0003`, абзацу — `doc_id:p003`.
Один абзац може потрапити в кілька чанків через перекриття, тому `label_cli.py` пропонує всі такі чанки як gold.

## Рішення й відкинуті альтернативи

- BM25 написаний вручну замість `rank_bm25`: залежність не потрібна для 60 рядків формули.
- Векторний пошук — множення матриці в numpy замість FAISS: корпус малий, індекс у пам'яті.
- Ембединги локальні через `sentence-transformers` замість API: дві багатомовні моделі порівнюються без мережевих викликів і без ключа.
- Профілі ембедингів зберігають префікси окремо, бо e5 потребує `query: ` і `passage: `, а MiniLM — ні.
- Реранкер — крос-енкодер `BAAI/bge-reranker-v2-m3`, налаштовується одним рядком.
- RRF замість зваженої суми балів: BM25 і косинус мають несумірні шкали.
- Перекриття береться цілими реченнями, щоб не різати цитату посередині.
- Чанк не перетинає межу розділу й не бере перекриття через неї: мітка розділу в чанку завжди відповідає всьому його тексту.
- Токенізація без стемінгу: український стеммер без залежностей ненадійний, а помилкові основи псують видачу.
- Генерація пропускається, коли пошук нічого не повернув: відповідь «Недостатньо даних у корпусі» не коштує виклику моделі.
- Відкинуто HyDE і розширення запиту через LLM: додають виклик і затримку до того, як виміряно базові режими.
- Відкинуто збереження індексу в SQLite: JSONL і `.npy` читаються без схеми й міграцій.

## Оцінка якості

Набір готує людина.
`tools/label_cli.py` показує абзац, питає питання й дописує рядок у `data/eval.jsonl` з полями `id`, `question`, `gold_chunk_ids`.
`tools/draft_questions.py` пропонує кандидати через LLM у `data/eval_candidates.jsonl` зі статусом «потребує ручної перевірки» і не торкається `eval.jsonl`.
`eval.py` відмовляється рахувати метрики на порожньому наборі.

Метрики пошуку для кожного режиму:
- `recall@k` для k=1,3,5 = кількість gold-чанків у топ-k, поділена на кількість gold-чанків.
- `MRR` = середнє `1/ранг` першого gold-чанка в межах виданого `top_k`.

Метрика генерації:
- частка відповідей, де кожна цитата вказує на чанк із контексту.
- Відповідь без жодної цитати не зараховується і рахується окремо в `no_citation_answers`.
- Виклики з помилкою не входять у знаменник і рахуються в `failed`.

Результати ще не отримані.

| Режим | Ембединги | recall@1 | recall@3 | recall@5 | MRR | p50 пошуку, мс |
|---|---|---|---|---|---|---|
| bm25 | — | не виміряно | не виміряно | не виміряно | не виміряно | не виміряно |
| vector | e5-base | не виміряно | не виміряно | не виміряно | не виміряно | не виміряно |
| vector | minilm-l12 | не виміряно | не виміряно | не виміряно | не виміряно | не виміряно |
| hybrid | e5-base | не виміряно | не виміряно | не виміряно | не виміряно | не виміряно |
| hybrid | minilm-l12 | не виміряно | не виміряно | не виміряно | не виміряно | не виміряно |
| hybrid_rerank | e5-base | не виміряно | не виміряно | не виміряно | не виміряно | не виміряно |

| Генерація | Відповідей | Усі цитати в контексті | Частка |
|---|---|---|---|

`eval.py` перезаписує `results/metrics.md` і пише `results/eval_<час>.json` та `results/details_<час>.jsonl`.
Файл деталей містить видані чанки, gold і текст відповіді для розбору помилок.

## Вартість і затримка

Кожен виклик моделі дописує рядок у `results/calls.jsonl`: час, тип, модель, вхідні токени, вихідні токени, затримка, статус.
Типи: `chat`, `embedding`, `rerank`.
Токени для локальних моделей рахуються токенізатором моделі; якщо токенізатор недоступний, поле лишається `null`.
Вартість рахується з цих логів за цінами `llm.price_per_1m_input` і `llm.price_per_1m_output`.
Ціни не задані, доки їх не вписано в конфіг, тому вартість лишається `null`.

Затримка пошуку міряється навколо `Retriever.search` і включає кодування запиту та реранкінг.
Побудова індексу в затримку запиту не входить.
Повторні запуски беруть ембединги з кешу, тому час кодування корпуса в логи не потрапляє.

| Тип | Модель | Викликів | Вхідні токени | Вихідні токени | p50, мс | p95, мс | Вартість |
|---|---|---|---|---|---|---|---|
| chat | не виміряно | не виміряно | не виміряно | не виміряно | не виміряно | не виміряно | не виміряно |
| embedding | не виміряно | не виміряно | не виміряно | не виміряно | не виміряно | не виміряно | не виміряно |
| rerank | не виміряно | не виміряно | не виміряно | не виміряно | не виміряно | не виміряно | не виміряно |

## Що зламалося

Прогону на реальному корпусі ще не було. Нижче — режими відмови, які видно з коду й тестів.

### Нарізка ламає умови з винятками

Правило й виняток часто стоять у сусідніх реченнях одного абзацу.
Пакувальник закриває чанк, коли додавання наступного речення перевищує `target_chars`.
За малого `target_chars` правило потрапляє в один чанк, а виняток — в інший.
Пошук повертає чанк із правилом, і модель відповідає «10 днів» без згадки про 30 днів для державних замовників.
Перекриття рятує лише тоді, коли виняток лежить у межах `overlap_chars` від границі.
Заголовок розділу в індексованому тексті не допомагає, бо винятку в тексті чанка просто немає.
Тести `test_exception_separated_from_rule_with_small_target` і `test_exception_kept_with_rule_when_target_large` фіксують обидва випадки.
Часткові пом'якшення зараз: перекриття цілими реченнями, вимога наводити винятки в системному промпті.
Повне пом'якшення — розширення контексту сусідніми чанками того самого розділу — заплановане.

### Інші відомі межі

- BM25 без лематизації не знаходить «оплати» за запитом «оплата». Українська морфологія лишається непокритою.
- `hard_max_chars` ріже суцільне слово довше за ліміт посередині. Тест це фіксує.
- Перекриття роздуває gold-набір: один абзац дає кілька валідних чанків, і `recall@k` зростає без покращення пошуку.
- Префікси e5 прив'язані до профілю. Перемикання `repo` без зміни префіксів псує якість мовчки.
- Реранкер навчався на багатомовних даних без гарантії української. Якість на цьому корпусі не перевірена.
- `eval.py` ловить помилку окремого режиму і ставить «не виміряно» замість падіння всього прогону.
- Порожній `data/eval.jsonl` зупиняє оцінку з кодом 2.

## Як запустити

Швидкий шлях без моделей і без ключа:

```bash
python -m venv .venv && source .venv/bin/activate
pip install -e ".[dev]"
python tools/build_index.py --embeddings none
python ask.py "Який строк оплати для державних замовників?" --mode bm25 --no-generation
pytest -q
```

Повний шлях:

```bash
pip install -e ".[vector,dev]"
cp .env.example .env
# впиши LLM_API_BASE, LLM_API_KEY, LLM_MODEL
set -a; source .env; set +a

# поклади файли корпусу в data/corpus і видали example_structure.md
python tools/build_index.py --embeddings all

python tools/label_cli.py            # розміть питання вручну
# або: python tools/draft_questions.py --limit 20, потім перевір кандидати руками

python eval.py
```

Корисні прапорці:
- `ask.py --mode bm25|vector|hybrid|hybrid_rerank --top-k 5 --embedding-model minilm-l12`
- `eval.py --modes bm25 hybrid --limit 20 --no-generation`
- `tools/build_index.py --rebuild`

Файл `.env` не читається автоматично, змінні експортує shell командою `set -a; source .env; set +a`.
Результати оцінки: `results/metrics.md`, `results/eval_<час>.json`, `results/details_<час>.jsonl`.
