# rag-uk

RAG-пошук по українськомовних документах з дослівними цитатами у відповіді та оцінкою якості на розміченому наборі питань.

Система нарізає документи на чанки, шукає відповідь одним із чотирьох способів і просить LLM відповісти лише з знайденого контексту. Кожне твердження у відповіді має підтверджуватися цитатою в лапках і ідентифікатором чанка, наприклад `[договір:0003]`. Ідентифікатор, якого не було в контексті, рахується помилкою.

Мета репозиторію: порівняти режими пошуку на власному корпусі й побачити, де вони помиляються, а не лише отримати працюючий чат.

## Режими пошуку

| Режим | Що робить |
|---|---|
| `bm25` | Лексичний пошук Okapi BM25, без моделей і без мережі |
| `vector` | Косинусна подібність до ембедингів чанків |
| `hybrid` | BM25 і векторний пошук, об'єднані через reciprocal rank fusion |
| `hybrid_rerank` | Кандидати з `hybrid`, переоцінені крос-енкодером |

Ембединги: `intfloat/multilingual-e5-base` і `paraphrase-multilingual-MiniLM-L12-v2`, обидві локально через `sentence-transformers`. Реранкер: `BAAI/bge-reranker-v2-m3`. Моделі змінюються в `config.yaml`; префікси `query:` і `passage:` для e5 зберігаються разом із профілем.

## Швидкий старт без моделей і ключів

Потрібен Python 3.11 або новіший.

```bash
python -m venv .venv && source .venv/bin/activate
pip install -e ".[dev]"
python tools/build_index.py --embeddings none
python ask.py "Який строк оплати для державних замовників?" --mode bm25 --no-generation
pytest -q
```

Команда `ask.py` покаже знайдені чанки з розділом і номерами абзаців. Корпус у `data/corpus/` складається з одного прикладу, який потрібно замінити своїми `.md` або `.txt` файлами. Заголовки `#` визначають розділи.

## Повний запуск

```bash
pip install -e ".[vector,dev]"
cp .env.example .env          # впиши LLM_API_BASE, LLM_API_KEY, LLM_MODEL
set -a; source .env; set +a   # .env не читається автоматично

python tools/build_index.py --embeddings all
python tools/label_cli.py     # ручна розмітка питань
python eval.py
```

Клієнт працює з будь-яким OpenAI-сумісним `/chat/completions`, зокрема з локальним сервером. Назва моделі не задана за замовчуванням: без `LLM_MODEL` система показує лише знайдені чанки.

## Оцінка

Набір питань розмічає людина. `tools/label_cli.py` показує абзац, питає питання і дописує рядок у `data/eval.jsonl`:

```json
{"id": "q-0001", "question": "…", "gold_chunk_ids": ["договір:0004"]}
```

`tools/draft_questions.py` може запропонувати кандидатів через LLM, але пише їх в окремий файл зі статусом «потребує ручної перевірки» і не торкається `eval.jsonl`. На порожньому наборі `eval.py` відмовляється рахувати метрики.

Що вимірюється:

- пошук: `recall@1`, `recall@3`, `recall@5` і `MRR` для кожного режиму та кожної моделі ембедингів;
- генерація: частка відповідей, де кожна цитата вказує на чанк із контексту; відповіді без цитат рахуються окремо;
- вартість і затримка: кожен виклик моделі (чат, ембединги, реранкер) логується в `results/calls.jsonl` з токенами та часом; вартість рахується, лише якщо в конфігу задано ціни.

Результат лягає в `results/metrics.md`, `results/eval_<час>.json` і `results/details_<час>.jsonl`.

**Чисел поки немає.** Прогону на реальному корпусі ще не було, тому будь-які метрики для цього репозиторію треба отримати самостійно.

## Конфігурація

Параметри лежать у `config.yaml` (розмір чанків, `k1` і `b` для BM25, `top_k`, `candidate_k`, `rrf_k`, таймаути й повтори LLM). Значення стартові, на корпусі не підбиралися. Змінні середовища перекривають файл:

| Змінна | Призначення |
|---|---|
| `LLM_API_BASE`, `LLM_API_KEY`, `LLM_MODEL` | Провайдер LLM |
| `RAG_CONFIG` | Шлях до іншого конфігу |
| `RAG_RETRIEVAL_MODE` | Режим пошуку |
| `RAG_EMBEDDING_MODEL` | Профіль ембедингів |

## Структура

```
ask.py             одне питання: пошук і відповідь із цитатами
eval.py            метрики по всіх режимах
rag_uk/            бібліотека: чанкінг, індекси, злиття, реранкер, LLM, цитати, метрики
tools/             побудова індексу, ручна розмітка, чернетки питань
tests/             136 тестів, моделі й мережа не потрібні
docs/DESIGN.md     рішення, відкинуті альтернативи, відомі режими відмови
```

## Відомі обмеження

- BM25 без лематизації: запит «оплата» не знайде «оплати». Морфологію української поки не покрито.
- Якщо правило й виняток опиняються в різних чанках, модель може відповісти за одним правилом. Розширення контексту сусідніми чанками розділу заплановане, докладніше в `docs/DESIGN.md`.
- Перекриття чанків збільшує кількість валідних gold-чанків для одного абзацу, тому `recall@k` частково залежить від налаштувань нарізки.
- Якість реранкера на українській не перевірена.
- Цитата перевіряється за ідентифікатором чанка, а не за дослівним збігом тексту.
